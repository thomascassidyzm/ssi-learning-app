# Backfill: `schools.trial_course_code` — applied 2026-08-07

Founder report (B1, Chepstow-mirror testing): the school card on a school
leader's home page showed a state badge reading a bare **"Trial"** with no
language.

## The writer gap

An **invite-born** school (`api/code/redeem.ts`, `school_admin` branch) redeems
with no course chosen — an invite only ever carries a `school_name` label, never
a course code — so `provisionSchoolPlatformTrial(..., courseCode: null, ...)` is
correct at that moment. The gap was that **nothing ever filled it in
afterwards**: the school went on to teach `cym_s_for_eng` in every one of its
classes while `schools.trial_course_code` stayed null forever.

Verified on the live rows:

| school | `invite_code_id` | `trial_course_code` | classes |
|---|---|---|---|
| Ysgol Cas-gwent Chepstow School (`0f5bd6e4…`) | set → invite-born | `NULL` | 3 × `cym_s_for_eng` |
| ZZ Chepstow Mirror School (`ec608982…`) | null (mirror of the above, copied the null) | `NULL` | 3 × `cym_s_for_eng` |
| ZZ Test School (`5ef8f201…`) | — self-serve `provision.ts` | `cym_s_for_eng` | — |

Self-serve signup (`api/onboarding/provision.ts`) always passes the course
chosen at signup, which is why the contrast school was fine.

**Fix:** `ensureSchoolTrialCourse()` in `api/_utils/schoolPlatformTrial.ts`,
called from `POST /api/teacher/create-class-learner` — the unconditional
server hop that class creation already makes. The first class carrying a course
is the honest moment a school commits to the language it is trialling.
Fill-once (guarded on `trial_course_code IS NULL` AND
`platform_status LIKE 'trial%'`), so it can never overwrite a committed course
or touch a paying school. Fail-open, like every other platform-trial write.
