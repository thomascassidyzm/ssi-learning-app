# docs/ — what is in here, and what it is worth

This tree was emptied once. On Tom's ruling of 2026-08-24 — *"let's properly archive the docs so
the workers are not tempted to read them"* — the whole documentation estate moved, with its
history, to **`archive/docs-retired-2026-08-24/`**. Go there only for archaeology, never to answer
a question about how the system behaves today.

It did not stay empty. On `dev` at 2026-09-17 this directory carried 427 tracked files, 105 of its
124 markdown files written after that ruling; `main` lags a promotion or two behind and is
otherwise the same tree. So read this directory for what it is: mostly a dated record of what
somebody found on the day they wrote it, plus a handful of files that are genuinely current and a
set of build outputs.

**The code and the live DB are gospel.** Before acting on any claim you find in a document here —
an audit, a design note, a report, this README — verify it against the running code. If the code
cannot answer the question, **ask Tom one plain question** rather than trusting a document.

## Three kinds of file

### Standing, and kept current

- **`DECISIONS.md`** — the repo's decision journal, written on most jobs. Newest entry at the top.
- **`ROADMAP-PUBLIC.md`** — handed word for word to the in-app support drafter when a learner or
  admin asks what is coming. It is learner-facing copy, not notes. Its own header carries the
  rules for editing it.

### Build outputs and probe captures — treat these as code

- **`explainer-pack.md`, `walkthrough-pack.md`, `handbook-pack.md`** — regenerated by
  `tools/explainer/compile.mjs` and `tools/walkthrough/compile.mjs`. Never hand-edit them.
- **Screenshots and captures** under `the-view/`, `the-lens/`, `a159-htw-visual/`, `perf/`,
  `org-account/`, `navbar-redesign/`, `structure-redesign/`, `explainer/`, `the-model/`,
  `chepstow-three-bugs/` and others — these are where the e2e probe scripts under
  `packages/player-vue/e2e/` and `e2e/` write. 244 images in all.
- **A few JSON files** under `pod-position-audit/` and `pods/` are read by scripts in `tools/`.
- **`board/`** is authored prose only. The old build-time `?raw` import is gone: `/board/:code`
  renders a frozen `board_snapshots` row from `GET /api/board/snapshot/:code`.
- **`specimens/`** holds the worked examples that settled the class brain and the class-stats
  figures. The code comments in `api/_utils/classBrain.ts` point at them.

### Dated job write-ups — the bulk of it

Most of the markdown here is one worker's report of one investigation, named with the date it was
written. It is evidence of what was true on that date. Nothing goes back to correct it afterwards,
and it is never an authority for today. Read one to learn how a thing was measured, then verify
every claim in it against the running code before you act.

## Elsewhere

At the repo root, `CHANGELOG.md` is Tom's own per-promotion prose
(`tools/release-train/release-notes.mjs`), a ledger rather than documentation; `WORKLIST.md` is the
live shared "what's next". Both are outside this tree on purpose.
