## Why this matters

`pnpm audit --prod` reports 11 vulnerabilities including **1 critical + high
severity issues in `fast-xml-parser`**, reached through an outdated
`@aws-sdk/client-s3@^3.975.0`. That AWS path is the server-side audio proxy
(`api/audio/[audioId].ts`), which parses XML responses from S3 — exactly where an
entity-expansion DoS / encoding-bypass advisory bites. These are fixable by a routine
version bump, no code change.

## Scope

**In scope**:
- `package.json` (root) — bump `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner`.
- `packages/player-vue/package.json` — bump `echarts` if a patched minor exists.
- `pnpm-lock.yaml` — regenerated by `pnpm install` (this is the one lockfile change
  this plan legitimately makes).
- Optionally, a `pnpm.overrides` block in root `package.json` for `fast-xml-parser`
  and `ws` if the SDK bump alone doesn't clear them.

**Out of scope**:
- Any application source change. If a bump breaks a type or test, that's a STOP.
- Major version bumps of any package (e.g. echarts 5→6, aws-sdk staying on 3.x only).
- vitest (that's plan 017).

## Steps

### Step 1: Bump the AWS SDK

Update both `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` to the latest
`3.x` (keep the `^3.` range, pick the current newest 3.x that ships
`fast-xml-parser >= 5.3.8`). Run `pnpm install`.

**Verify**: `pnpm why fast-xml-parser` shows a version `>= 5.3.8`; `pnpm audit --prod`
no longer lists the fast-xml-parser critical/high.

### Step 2: Add overrides only if needed

If any critical/high remains for `fast-xml-parser` or `ws` after Step 1, add a
`pnpm.overrides` block to root `package.json` pinning the transitive to its patched
version, and re-run `pnpm install`. Prefer the SDK bump; use overrides only as a
fallback.

**Verify**: `pnpm audit --prod` reports **0 critical and 0 high**.

### Step 3: Bump echarts if a safe minor exists

If a `5.x` patch of echarts clears the moderate advisory, bump it in
`packages/player-vue/package.json`. If only a major (6.x) fixes it, leave echarts and
note it in Maintenance (moderate, chart lib, not server-side).

**Verify**: `pnpm audit --prod` moderate count reduced or documented as major-only.

### Step 4: Prove nothing broke

Run all verification gates and a player build (the AWS SDK is used by serverless code;
the build proves the player still compiles, and the API tests cover the audio proxy).

**Verify**: typechecks, both test suites, and `pnpm --filter player-vue build` all
pass.

## Test plan

`api/audio/[audioId].ts` and `_utils/audioAccess.ts`) plus a clean build. If a test
that exercises the S3 client fails after the bump, that's a real incompatibility —
STOP.

## STOP conditions

Stop and report if:
- Clearing the critical/high requires a **major** version bump of the AWS SDK (4.x)
  or of `ws`, or an app-source change.
- A test or the build fails after the bump (real incompatibility).
- `pnpm audit --prod` shows a different critical advisory than fast-xml-parser (the
  advisory landscape drifted — re-scope).
