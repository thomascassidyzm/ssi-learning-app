## Recommended sequencing

The order above is roughly leverage-ranked, but the load-bearing dependencies are:

- **001 first.** It protects everything after it. Its `pnpm typecheck:api` /
  `pnpm test:api` gates automatically get stronger as 002 and 004 land.
- **002 and 004 feed 001** — they give the CI gate more surface to protect (the whole
  api typecheck; the money-path tests).
- **004 before 009 and 021** — never touch money code without its characterization
  tests in place. 021 (Paddle build) hard-requires 004.
- **020 before/with 021** — the all-languages-on-paid collapse simplifies what the
  Paddle build must grant (a seat, not per-course entitlements).
- **005 / 006 / 013 before 019** — finish the SimplePlayer/cache bug fixes before the
  refactor pass, so extractions don't collide with them (all touch overlapping files).
- **018 benefits 022** — the server-mediated scope endpoint 018 builds is the pattern
  022 reuses to wire Insight widgets to real data.
- **016 and 017 both touch player-vue devDependencies** — don't run them concurrently.

Plans that share a file (coordinate drift, don't run in parallel on the same file):
- `SimplePlayer.ts`: 005, 006, 013, and (later) 019.

## Findings considered and rejected (so they aren't re-audited)

- **Audio paywall fails open by default** (`api/_utils/audioAccess.ts:171-178`,
  `ENTITLEMENT_STRICT` off) — NOT a bug. In-code comments show this is a deliberate,
  tracked fail-open pending client entitlement-token rollout; flipping it early would
  lock out live payers. It's an operational milestone to track (flip `ENTITLEMENT_ENFORCE
  =strict` once token-attachment telemetry is healthy), not a code defect. Plan 011
  hardens the *secret* used by that system; the strict-mode flip is deliberately out of
  scope.
- **Bundle composition** — already good. `packages/player-vue/vite.config.js` does
  route-level splitting, vendor/core/echarts `manualChunks`, lazy `import('echarts')`,
  and SW-precache exclusion of admin/schools/echarts chunks. No plan needed.
- **APML "spec per commit" mandate** — being honored (70+ commits touching `apml/`
  since June). No plan needed.
- **RLS off on the six org tables** — deliberate, condition-gated (documented runbook in
  `CLAUDE.md`). The endpoint-level authz within that architecture was audited and found
  solid (webhook signatures verified, crons fail closed, admin-write siblings scoped
  server-side, no forged-payload escalation). Plan 018 advances one of its stated
  preconditions (repoint client reads); the RLS flip itself is not planned here.
- **WORKLIST.md grooming** (bloated `[x]` entries) — real but low-leverage housekeeping;
  the groomer routine is already a claimed open item on the worklist itself. Not planned.
