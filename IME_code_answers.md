## Q1. High-level platform architecture

### One-paragraph summary

The platform is a single web application (a Vue 3 single-page app, installable as a Progressive Web App) that serves both learners and schools, deployed on Vercel. It talks to two backends: a Supabase-hosted PostgreSQL database (course structure, learner progress, schools data, authentication) and a set of Vercel serverless functions in this repo (audio delivery, payments, entitlements, admin operations). Course audio is stored in AWS S3 and served through the app's own audio proxy endpoint. Course *content creation* happens in a separate system entirely (a different repo) — this repo only delivers content. A legacy native mobile app exists but is **not in this repo**.

### Component by component

**1. The web app (learner player) — implemented, the core of the platform**
- Vue 3 SPA in `packages/player-vue/` (dependencies: `vue ^3.5.24`, `vue-router`, `@supabase/supabase-js`, `@paddle/paddle-js`, `idb`, `workbox-window` — `packages/player-vue/package.json`).
- Built with Vite and deployed to Vercel: `vercel.json` sets `buildCommand: "pnpm --filter @ssi/core build && pnpm --filter player-vue build"` and `outputDirectory: "packages/player-vue/dist"`.
- It is a PWA: `vite-plugin-pwa` / Workbox service worker configured in `packages/player-vue/vite.config.js` (line 3, 48+), with IndexedDB used for offline audio caching (`idb` dependency; cache code under `packages/player-vue/src/cache/` and offline composables).
- The learning engine (the 4-phase prompt/pause/voice cycle, spaced repetition, session orchestration) is a framework-agnostic TypeScript package `@ssi/core` in `packages/core/`, consumed by the Vue app (`"@ssi/core": "workspace:*"` in player-vue's package.json).

**2. The mobile app — not in this repo**
- There is **no mobile app code in this repository**. A legacy native app built in Flutter exists in a separate repository; this repo only documents it. `docs/native-migration-feasibility.md` (2026-06-03) describes the Flutter app as having strictly less functionality than the web app and lays out a **planned** (not started, as far as this repo shows) migration to a Capacitor-wrapped build of this same web app. Any due diligence on the current mobile app must be done against the Flutter repo, which we'd need to identify and check separately.
- The legacy native app consumes pre-rendered course content via a `course_manifest.json` (described in `CLAUDE.md` "TRANSITION STATE" section); the manifest is generated by the separate dashboard repo, not here.

**3. The schools interface — implemented, inside the same web app**
- Not a separate application. It is a path-based section of the same Vue SPA at `/schools`: `vercel.json` rewrites `/schools` and `/schools/(.*)` to `/schools/index.html`; layout/auth in `packages/player-vue/src/containers/SchoolsContainer.vue`; ~12 views in `packages/player-vue/src/views/schools/`; data layer of ~16 composables in `packages/player-vue/src/composables/schools/`.
- Four roles (govt_admin, school_admin, teacher, student) with sign-in via email OTP (see `SchoolsContainer.vue`; server-side OTP verification at `api/email/verify.ts`).

**4. The content / course system — split across two repos and two stores**
- **Content creation is NOT in this repo.** Courses are authored in a separate repository (`ssi-dashboard-v7-clean`, internally "Popty" — referenced throughout `CLAUDE.md` "Ecosystem: Two Repositories"). That repo would need separate review.
- **Content storage — implemented:** course structure (seeds, LEGOs, practice phrases, audio metadata) lives in Supabase PostgreSQL tables (`course_seeds`, `course_legos`, `course_practice_phrases`, `course_audio` — query patterns documented in `CLAUDE.md` and used by `packages/player-vue/src/providers/CourseDataProvider.ts`). Database migrations that this repo controls are in `supabase/migrations/` (19 files, June–July 2026) plus `supabase/schema.sql`.
- **Audio storage — implemented:** audio files live in an AWS S3 bucket. Defaults in code: bucket `ssi-audio-stage`, region `eu-west-1` (`api/_utils/audioAccess.ts:36-44`, `packages/player-vue/src/config/env.ts`), overridable by environment variables (`S3_AUDIO_BUCKET`, `AWS_REGION`, etc.). The production bucket name/config is set in Vercel environment variables — **not visible in this repo**.

**5. Backend services — implemented, two kinds**
- **Serverless API (this repo):** TypeScript functions under `api/` deployed as Vercel functions (`@vercel/node` in root `package.json`). Main areas: audio delivery proxy with entitlement checks (`api/audio/[audioId].ts`, `api/audio/batch-urls.ts`), subscriptions via Paddle (`api/subscription/`, `api/_utils/paddle.ts`), teacher payouts via Wise on a monthly cron (`api/cron/teacher-payouts.ts`, scheduled `0 6 1 * *` in `vercel.json` "crons"), admin operations (`api/admin/`), schools/teacher/group endpoints, entitlement grants, invite codes, email verification.
- **Supabase (external service):** PostgreSQL + authentication (email OTP) + PostgREST API. The client app queries it directly with a public "anon" key (`packages/player-vue/src/config/env.ts` — `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`); serverless functions use a privileged service-role key (`SUPABASE_SERVICE_ROLE_KEY`, e.g. `api/_utils/audioAccess.ts:22`). The live Supabase project itself (its settings, live row-level-security state, backups) is **not visible in this repo** — only the migration files are.

### How the pieces communicate

- Browser → Supabase: direct HTTPS queries via the Supabase JS client (course data, progress, schools data).
- Browser → Vercel serverless functions: HTTPS to `/api/*` on the same domain (audio, payments, admin, anything needing server-side privileges).
- Serverless functions → Supabase: service-role client (server-only key).
- Serverless functions → AWS S3: AWS SDK (`@aws-sdk/client-s3`, `@aws-sdk/s3-request-presigner` in root `package.json`); audio is streamed through `/api/audio/:audioId` or delivered via short-lived presigned S3 URLs (`api/audio/batch-urls.ts`; recent commit `4d58759` notes presigned URLs have a 5-minute TTL).
- Serverless functions → Paddle (payments) and Wise (payouts): via their official SDK/API with webhook signature verification (`api/_utils/paddle.ts`, `api/_utils/wise.ts`).

### Deployment and environments — implemented

- Vercel hosting with a three-tier branch promotion flow (`CLAUDE.md` branch policy): `dev` branch → dev preview URL; `staging` branch → staging.saysomethingin.app; `main` → saysomethingin.app (production). The domain/DNS/TLS configuration lives in the Vercel dashboard — **not visible in this repo**.

## Q2. Minimum OS versions, device requirements, app size, and content storage

### Native app (iOS / Android) minimums — not visible in this repo

There are **no native build configurations in this repository**. A search for `*.xcodeproj`, `Info.plist`, `build.gradle*`, `AndroidManifest.xml`, `Podfile`, and `capacitor.config.*` returns nothing (excluding node_modules). Therefore:

- **iOS deployment target: not visible in this repo.** It lives in the separate Flutter app repository.
- **Android minSdkVersion / targetSdkVersion: not visible in this repo.** Same — Flutter repo.

These values must be read from the Flutter repo before answering the partner definitively. The planned Capacitor wrap (`docs/native-migration-feasibility.md`) has **no code yet** — no Capacitor config exists, so no future minimums can be cited either.

### Web app browser requirements

There is **no explicit browser-support declaration**: no `browserslist` field in any `package.json` (checked root, `packages/player-vue`, `packages/core`) and no `.browserslistrc` file anywhere in the repo. The vite config (`packages/player-vue/vite.config.js`) does not set `build.target`. The effective requirements therefore come from tool defaults:

- **Build tool:** Vite `^7.2.4` (`packages/player-vue/package.json:44`). Vite 7's default build target is `'baseline-widely-available'`, which corresponds to approximately **Chrome/Edge 107+, Firefox 104+, Safari 16+ (≈ iOS 16+, released Sept 2022)**. *This is derived from the tool's documented default, not from an explicit config value in the repo — treat it as the practical floor, not a tested guarantee.*
- **TypeScript compile targets** (syntax floor only): `ES2020` for the app (`packages/player-vue/tsconfig.json:3`), `ES2022` for the core engine and serverless API (`packages/core/tsconfig.json:3`, `tsconfig.api.json:3`).
- **What is actually tested** (implemented — Playwright E2E matrix, `packages/player-vue/playwright.config.ts:34-56`): Desktop Chrome, Desktop Safari (WebKit), iPhone 14 emulation, Pixel 7 emulation. Real-device testing beyond these emulations is not visible in this repo.
- **Hard functional requirements** for full functionality: a service worker + IndexedDB capable browser (offline/PWA features — `vite-plugin-pwa ^1.2.0`, IndexedDB cache `packages/player-vue/src/cache/AudioCache.ts`, DB name `ssi-audio-cache-v2`). The app can run online-only without these, degrading offline capability.
- **PWA install properties** (`vite.config.js` manifest block): `display: 'standalone'`, `orientation: 'portrait'` — the installed app is portrait-only by manifest.
- No microphone, camera, or GPS requirement anywhere in the code — the learner speaks aloud but the app does not record (speech recognition is listed as "Future" in `CLAUDE.md`).

### Installed app size — measured from a local production build (commit `4d58759`, 2026-07-09)

There is no app-store binary from this repo; "install size" for the web app means what the PWA downloads:

- **PWA install payload (service-worker precache): ~2.3 MB** — build output reports `precache 199 entries (2331.28 KiB)`. This is the complete offline app shell every learner gets.
- Heavy modules are deliberately excluded from that install and fetched on demand only (`vite.config.js` `globIgnores`): the echarts charting library (~1,043 kB, admin/insight boards only), the eruda debug console (~506 kB, `?debug` only), the schools dashboard chunk (~244 kB), and admin chunks.
- Full static deployment payload is ~15 MB excluding sourcemaps (measured on `dist/`), but a learner's browser only ever downloads the shell plus the chunks they actually visit; all app JS combined is ~1.0 MB gzipped.

### Course content storage requirements

**How audio is stored:** as thousands of small "atomic" MP3 clips (one per phrase per voice), not as long lesson files. Delivered via `/api/audio/:audioId` or presigned S3 URLs, cached client-side in IndexedDB (`packages/player-vue/src/cache/AudioCache.ts`).

**Typical file size — implemented values in code:**
- The offline-download estimator uses **~24 KB per clip** as its fallback: `avgBytesPerFile = 24 * 1024  // ~24 KB/clip fallback (CLAUDE.md: 4.8 MB / 198 files)` (`packages/player-vue/src/components/LearningPlayer.vue:9608`), refined at runtime from actual cached-file sizes. A second estimator uses 25 KB/file (`packages/player-vue/src/composables/useScriptCache.ts:394`).
- The 15 sample MP3s bundled in the repo corroborate this: 340 KB total ≈ **~23 KB average** (`packages/player-vue/public/audio/`).
- Rounds average ~12 audio files each (fallback `avgFilesPerRound = 12`, `LearningPlayer.vue:9625`).

**Storage needed for downloaded content** (arithmetic from the code's own constants — ~4.8 MB per 30 minutes of lesson audio):

| Download option (`packages/player-vue/src/config/audioConfig.ts:34-37`) | Hours | Estimated size |
|---|---|---|
| Current belt | 0.5 | ~5 MB |
| Next 2 hours | 2 | ~19 MB |
| Next 5 hours | 5 | ~48 MB |
| Entire course | 10 | **~96 MB** |

So a full course held offline is on the order of **100 MB**, comfortably inside browser storage quotas. The app monitors quota via `navigator.storage.estimate()` and flags "low space" when usage exceeds 90% of quota (`AudioCache.ts:424-438` `quotaPressure()`; threshold `> 0.9` at `LearningPlayer.vue:9619`). `CLAUDE.md` cites a ~1 GB Safari storage limit as ~200× headroom for one course; the code treats iOS quota reporting as unreliable and uses the usage/quota *ratio* instead (comment at `LearningPlayer.vue:9613-9617`).

**Caveats:** the per-clip sizes above are the app's own estimation constants plus a 15-file sample; a definitive average would need a measurement across the production S3 bucket (**not visible in this repo**). Course length varies by course (the "entire course" option is capped at 10 hours of audio in the UI config); the storage needs of the legacy Flutter app (which uses pre-rendered 30–50 MB session files per `CLAUDE.md`) are **not visible in this repo**.
